## 2. Encounter Workflow Ownership Recommendation
* **KAN-4 (`encounters`):** Owns `OPEN` creation, `OPEN ↔ CODING_IN_PROGRESS` (via coding start), `→ CLOSED` administrative closure, and `DELETE` (only when zero dependents exist).
* **KAN-5 (`records`/`coding`):** Calls `EncounterService.markCodingInProgress(encounterId, actor, tx)` when AI parsing/coding begins.
* **KAN-6 (`validation`):** Calls `EncounterService.markValidated(encounterId, actor, tx)` **only** after `ValidationResult` rows exist with no `FAILED` status.
* **KAN-7 (`claims`):** Calls `EncounterService.markClaimSubmitted(encounterId, actor, tx)` **only** after a `Claim` reaches `SUBMITTED`.
